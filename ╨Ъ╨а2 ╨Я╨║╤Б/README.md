# Электронный кошелёк — КР №2 (JavaFX + JDBC)

Настольное JavaFX-приложение для информационной системы «Электронный кошелёк» из КР №1. Работает напрямую через JDBC с той же базой PostgreSQL: клиенты, кошельки с картами «Мир» и операции по ним.

Java 21 (подходит и более новая JDK), JavaFX 21, Maven, FXML, CSS, PostgreSQL 16 в Docker.

## Запуск

Нужны Docker Desktop (в состоянии Running) и JDK 21 или новее. Maven ставить не обязательно: в проекте есть Maven Wrapper (`mvnw`), он сам скачает Maven при первом запуске.

macOS / Linux:

```bash
./run.sh
```

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт выполняет `docker compose up -d --wait` (поднимает PostgreSQL и ждёт healthcheck), затем `mvnw javafx:run`.

То же вручную:

```bash
docker compose up -d --wait      # база данных
./mvnw javafx:run                # приложение (или mvn javafx:run, если Maven установлен)
```

Другие команды Maven: `./mvnw clean compile`, `./mvnw test`, `./mvnw clean package`.

В IntelliJ IDEA: открыть `pom.xml` как проект, выбрать JDK 21+, запустить класс `wallet.app.Launcher` или цель Maven `javafx:run`.

Остановка базы без потери данных: `docker compose down` (без флага `-v`, иначе том с данными удалится).

## База данных

Используется база КР №1: контейнер `electronic-wallet-db`, том `wallet_pg_data`, база `wallet_db`, пользователь `postgres`. В `docker-compose.yml` указано `name: electronic-wallet` — это тот же проект Docker Compose, что и в папке `ПКС_кр1`, поэтому КР №1 и КР №2 работают с одними и теми же данными.

С компьютера база доступна на порту **5433**. На этом компьютере порт 5432 занят локальным Postgres.app, и подключение к `localhost:5432` попадало не в Docker, а в него. Внутри контейнера PostgreSQL по-прежнему слушает 5432.

Параметры подключения лежат в `src/main/resources/database.properties`, а не в Java-коде. Их можно переопределить переменными окружения `DB_URL`, `DB_USER`, `DB_PASSWORD`.

Скрипты: `sql/schema.sql` (таблицы и ограничения) и `sql/data.sql` (тестовые данные: 8 клиентов, 8 кошельков, 15 операций). Docker выполняет их только при первом запуске на пустом томе.

Проверка состояния: `docker compose ps` — у контейнера должен быть статус `healthy`. Журнал базы: `docker compose logs postgres`.

Консольное приложение КР №1 публикует ту же базу на порту 5432. Если запустить его `run.sh`, контейнер пересоздастся с портом 5432 (данные останутся в томе). Скрипт `run.sh` КР №2 вернёт порт 5433.

## Возможности

| Вкладка | Что можно сделать |
| --- | --- |
| Клиенты | Основная сущность, полный CRUD. Регистрация (кошелёк выпускается автоматически), изменение, удаление с подтверждением. Справа карточка клиента: данные, карта «Мир», остаток лимита и все операции по кошельку |
| Кошельки | Смена статуса, новая операция по кошельку, переход к операциям кошелька |
| Операции | Пополнение, перевод, вывод. Кошельки выбираются из списка, а не вводятся по ID. Подробности операции, итоги по выборке |
| Статистика | 12 показателей, круговая диаграмма статусов и столбчатая диаграмма сумм по типам. Период для показателей «за период» |

На каждой вкладке есть поиск, фильтры, сортировка и кнопка «Экспорт таблицы…»: в файл попадают строки, которые сейчас видны в таблице, в текущем порядке. Кнопка «Обновить данные» в шапке (или F5) перечитывает всё из базы.

| Вкладка | Поиск | Фильтры | Сортировка |
| --- | --- | --- | --- |
| Клиенты | ФИО, email, телефон, номер кошелька | статус кошелька, период регистрации | ФИО, дата регистрации, баланс |
| Кошельки | номер, владелец, держатель, 4 последние цифры карты | статус, срок действия (действующие / просроченные) | номер, баланс, срок, владелец |
| Операции | описание, получатель, кошелёк, владелец | тип, кошелёк, период дат | дата, сумма (по возрастанию и убыванию) |

Кроме списка «Сортировка» можно щёлкать по заголовкам столбцов; Shift + щелчок добавляет второй столбец сортировки.

Правила КР №1 сохранены: у клиента ровно один кошелёк, он создаётся и удаляется вместе с клиентом. Операции не редактируются и не удаляются: это журнал движения денег, его изменение сломало бы балансы.

## Проверки и бизнес-правила

Ошибка показывается под конкретным полем, поле подсвечивается красной рамкой, форма не закрывается.

- ФИО: обязательно, до 150 символов, 2–3 слова, только буквы, пробел и дефис, каждое слово с заглавной буквы.
- Email: обязателен, до 150 символов, корректный формат, уникален (проверяется по базе).
- Телефон: `+7` и 10 цифр. Пробелы, скобки, дефисы убираются, `8…` превращается в `+7…`.
- Сумма: число больше 0, не больше 1 000 000 ₽ за операцию, не больше двух знаков после запятой. Можно писать через точку или запятую.
- Описание: необязательно, до 500 символов (счётчик под полем).
- Перевод: нужен другой кошелёк получателя; оба кошелька активны и не просрочены; хватает денег; переводы за сутки не больше 100 000 ₽.
- Вывод: нельзя списать больше остатка.
- Статусы: «Активен» → «Заблокирован» или «Закрыт», «Заблокирован» → «Активен» или «Закрыт», «Закрыт» не меняется. Закрыть можно только кошелёк с нулевым балансом.
- Удалить клиента можно, только если на кошельке нет денег.
- Период в фильтрах: дата «по» не раньше даты «с». Несуществующую дату (например, 31.02.2026) поле не принимает.

Последняя линия защиты — ограничения в самой базе (`CHECK`, `UNIQUE`, внешние ключи).

Отличие от КР №1: у нового перевода в колонке «Получатель» записывается номер кошелька («Кошелёк WLT-000003»), а не его технический ID.

## Архитектура

Вызов идёт сверху вниз: `FXML → Controller → Service → Repository (DAO) → PostgreSQL`. SQL есть только в пакете `wallet.repository`.

| Слой | Где | Задача |
| --- | --- | --- |
| View | `src/main/resources/wallet/view/*.fxml`, `styles.css` | Разметка окон и оформление |
| Controller | `wallet.controller` | Реакция на действия пользователя, заполнение таблиц и форм |
| Помощники интерфейса | `wallet.ui` | `DataModel` (общие `ObservableList`), `Dialogs`, `FormDialogs`, `ExportDialog`, `FormErrors`, `Tables` |
| Service | `wallet.service` | Бизнес-правила, транзакции, статистика, подготовка экспорта |
| Проверки и фильтры | `wallet.service.validation`, `wallet.service.filter` | Проверка ввода, условия поиска |
| DTO | `wallet.dto` | Строки таблиц (`ClientView`, `WalletView`, `TransactionView`) и значения форм |
| Repository / DAO | `wallet.repository` | JDBC-запросы через `PreparedStatement` |
| Database | `wallet.db` | Подключение и транзакции (`commit` / `rollback`) |
| Model | `wallet.model` | Клиент, кошелёк, операция, перечисления |
| Экспорт | `wallet.export` | Интерфейс `DataExporter`, реализации `CsvExporter` и `ExcelExporter` |
| Ошибки | `wallet.exception` | `BusinessException`, `ValidationException`, `DatabaseException`, `ExportException` |
| Запуск | `wallet.app` | `Launcher`, `WalletApplication`, `AppContext` (сборка зависимостей) |

## Ответы для защиты

**Как запускается система из архива через Docker и как проверить PostgreSQL и backend.** Из корня архива: `docker compose --env-file .env -f backend/docker-compose.yml up -d --wait`. Флаг `--wait` ждёт healthcheck контейнеров. Проверка: `docker compose -f backend/docker-compose.yml ps` (PostgreSQL — `healthy`), страницы http://localhost:8080/ и http://localhost:8080/actuator/health. Свою базу КР №2 проверяем `docker compose ps`.

**Как запускается JavaFX-приложение.** `Launcher.main` вызывает `Application.launch(WalletApplication.class)`. JavaFX вызывает `init()` (там `AppContext` создаёт репозитории и сервисы), затем `start(Stage)`: загружается `MainView.fxml`, создаётся `Scene`, окно показывается, `MainController.loadData()` читает данные из базы. Отдельный `Launcher` нужен, чтобы приложение запускалось из IDE и jar, когда JavaFX лежит в classpath.

**Stage, Scene, Node.** `Stage` — окно. `Scene` — содержимое окна, к ней подключается CSS. `Node` — любой элемент дерева интерфейса: кнопка, таблица, панель. У каждой формы своё окно: `Dialog` со своей `Scene`.

**Зачем FXML.** Разметка окна описывается отдельно от Java-кода: её проще читать и менять, а контроллер содержит только поведение.

**Как FXML связан с Controller.** Атрибут `fx:controller` указывает класс контроллера. Элемент с `fx:id="table"` попадает в поле `@FXML private TableView<…> table`. `onAction="#onAdd"` вызывает метод `onAdd()`. После загрузки FXMLLoader вызывает `initialize()`. Контроллеры создаёт фабрика `AppContext.createController`, поэтому сервисы передаются в конструктор. Вкладки подключены через `fx:include`, а их контроллеры внедряются в поля `walletsViewController` и `transactionsViewController` главного контроллера.

**Как обновляются данные в TableView.** `DataModel.reload()` читает всё из базы и вызывает `setAll` у трёх `ObservableList`. Цепочка `ObservableList → FilteredList → SortedList → TableView` пересчитывается сама, таблицы перерисовываются. Это происходит после каждого сохранения, удаления и по кнопке «Обновить данные». `Tables.keepSelection` возвращает выделение на ту же запись.

**Зачем ObservableList.** Обычный список не сообщает об изменениях. `ObservableList` уведомляет подписчиков (таблицы, фильтры, счётчики строк, статистику), поэтому интерфейс не нужно обновлять вручную.

**Где бизнес-логика.** В `wallet.service`: `ClientService` (регистрация с выпуском кошелька, изменение, удаление), `WalletService` (статусы, номера кошельков и карт), `TransactionService` (движение денег, лимит), `StatisticsService`. Проверки формата — в `wallet.service.validation`.

**Где работа с данными.** В `wallet.repository`: интерфейсы и JDBC-реализации, только `PreparedStatement` с параметрами `?`. Изменения из нескольких запросов идут в `Database.inTransaction` (`setAutoCommit(false)`, `commit`, при ошибке `rollback`). Баланс меняется после `SELECT … FOR UPDATE`, кошельки блокируются по возрастанию ID, чтобы встречные переводы не заблокировали друг друга.

**Как обрабатываются исключения.** `BusinessException` — нарушено правило, показывается предупреждение. `ValidationException` — ошибки по полям, показываются под полями формы (`FormErrors.submit`). `DatabaseException.of` переводит код PostgreSQL (SQLState) в понятный текст: «нет подключения», «неверный пароль». Подробности и stack trace пишутся в журнал через SLF4J, пользователь их не видит. Необработанные исключения ловит `UncaughtExceptionHandler` и показывает короткое сообщение.

**Как проверяются данные.** В три слоя: `ClientValidator` и `TransactionValidator` (формат, длина, диапазоны), сервисы (уникальность email, статус и срок кошелька, остаток, лимит, переходы статусов — с обращением к базе), ограничения базы.

**Как реализованы поиск и фильтрация.** Условия собираются в record-фильтр (`ClientFilter`, `WalletFilter`, `TransactionFilter`). Метод `matches` проверяет строку, `FilteredList.setPredicate(filter::matches)` применяет его к таблице. Поиск не учитывает регистр и разницу «е/ё», запрос делится на слова, и каждое слово должно найтись в одном из полей. Сортировка: `SortedList.comparatorProperty()` привязан к `table.comparatorProperty()`, а пункт списка «Сортировка» задаёт `sortOrder` таблицы — так же, как щелчок по заголовку.

**Как рассчитывается статистика.** `StatisticsService.calculate` получает списки клиентов, кошельков и операций и считает показатели через Stream API: количество, доли, суммы, среднее, минимум, максимум, отбор по периоду. Результат — record `Statistics`, его метод `indicators()` выдаёт карточки и строки для экспорта.

**Как выполняется экспорт.** `ExportService` превращает текущие строки таблицы в `ExportTable`. `ExportDialog` открывает `FileChooser`: стартовая папка — «Документы» текущего пользователя, путь в коде не зашит. Формат выбирается по расширению: `CsvExporter` (UTF-8 с BOM, разделитель «;», открывается в Excel) или `ExcelExporter` (Apache POI, `.xlsx` с жирной шапкой и денежным форматом).

`./mvnw test` — 35 модульных тестов без базы данных: проверка ФИО, email, телефона, суммы, алгоритм Луна, фильтры, статистика.

## Отличия pom.xml от шаблона из задания

- Убран Jackson: в шаблоне он нужен демо-клиенту для JSON из REST API, а здесь работа идёт через JDBC.
- Добавлены `poi-ooxml` (экспорт в `.xlsx`) и `log4j-to-slf4j` (журнал Apache POI идёт в тот же SLF4J).
- Главный класс — `wallet.app.Launcher`.
- `--enable-native-access=javafx.graphics` убирает предупреждение новых JDK при запуске JavaFX.
